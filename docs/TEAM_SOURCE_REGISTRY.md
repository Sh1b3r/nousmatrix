# Реестр источников для отрядов и билдов HSR

Последняя проверка: **14 ноября 2026**. Версия, для которой проект сейчас хранит составы: **4.7**.

Этот файл нужен, чтобы новые команды добавлялись только с проверяемым основанием. Статистика прохождений, рекомендации автора, данные о механиках и оценки реликвий — разные типы свидетельств. Их нельзя смешивать под одной меткой «лучшая команда».

## Что известно о версии 4.7

На момент проверки я не нашёл открытой выборки прохождений MoC/PF/AS/AA за 4.7. Для текущего реестра использованы самые свежие доступные открытые записи версии 4.6.x:

- [Prydwen: Memory of Chaos](https://www.prydwen.gg/star-rail/memory-of-chaos) показывает цикл **4.6.2**, обновлённый 5 ноября 2026 года: 8 504 игрока. Данные охватывают MoC 12; среднее число циклов считается сразу по всем узлам, а выборка E0 ограничивает только ограниченных пятизвёздочных персонажей — стандартные пятизвёздочные и четырёхзвёздочные могут иметь эйдолоны.
- В [обработанном MocDataProcessed](https://huggingface.co/datasets/LvlUrArti/MocDataProcessed/tree/14bbf60e92714438d942c85f833344c45b5596b0/4.6.4) найден отдельный набор **4.6.4** с командами и метриками MoC, PF, AS и AA. Файлы закреплены за коммитом `14bbf60e92714438d942c85f833344c45b5596b0`. Он ближе к версии 4.7, но всё ещё не является статистикой 4.7; для записей команд в этом наборе не опубликован фильтр E0 или размер выборки каждой отдельной четвёрки.
- [AstraVoy: Team Rankings](https://astravoy.net/hsr/team-rankings?investment=all) при проверке показывал последние три цикла **4.4.1–4.6.1**, девять встреч и 142 940 команд для выбранного фильтра. Рейтинг складывает оценки использования и результатов с весами 40/60. Это ранг по их формуле, а не доказательство универсально лучшей команды.

Следствие: гайд, обновлённый к 4.7, можно пометить как рекомендацию автора 4.7, но нельзя выдавать его за статистику прохождений 4.7.

## Покрытие всего ростера

Ростер [AstraVoy](https://astravoy.net/hsr/characters) на дату сбора содержит **94 записи персонажей/форм**. В `src/data/teamStatistics.json` есть запись источника для каждого ID. Точные исторические команды найдены для **87 из 94**:

- Для **62 персонажей** взяты опубликованные AstraVoy составы по частоте использования из наборов версий 4.6, 4.5 и 4.4: до десяти строк на персонажа, с числом наблюдений, долей и числом контекстов.
- Ещё для **25 персонажей**, по которым AstraVoy не показал точных составов, добавлены наиболее часто использовавшиеся точные четвёрки по режимам из MocDataProcessed 4.6.4. Сохранены исходные режим, доля использования, место в таблице и средний результат, если он опубликован. Выборка не фильтруется по E0.
- Для **Арлана, Хука, Луки, Юйкун, Эона ★ Аха и Первопроходца (Разрушение/Сохранение)** эти источники не публикуют пригодных точных составов. В проекте для них есть явная запись отсутствия данных; замены по Пути/роли и выдуманные четвёрки не подставляются.

AstraVoy и обработанные таблицы MocData не считаются двумя независимыми источниками: в обоих случаях первичные прохождения происходят из MocData. Для некоторых одних и тех же четвёрок в записи приложены метрики 4.6.4 по конкретным режимам, когда исходный набор содержит точное совпадение.

Все статистические команды помечаются как **исторические наблюдения**, а не рекомендации или «лучшие команды». Счётчики команд не равны уникальным аккаунтам; у MocDataProcessed нет открытого размера выборки каждой отдельной четвёрки, а фильтр E0 не применён. До публикации статистики 4.7 эти записи могут быть устаревшими. Они нужны для прозрачного просмотра реально встречавшихся составов; автоматически заданные баффы и их длительность в симулятор не добавляются.

### Как считать статистическое подтверждение

Для записи команды нужны прямой URL на цикл/встречу, дата проверки, режим, версия, точные четыре персонажа, размер выборки/покрытие, фильтр эйдолонов и понятная метрика. В карточке нужно писать именно «часто используется», «показала такой-то результат» или «рекомендована автором» — не подменять это универсальным «лучшая».

Два сайта не считаются независимым подтверждением, если используют один и тот же набор прохождений. Большой индекс или частота сами по себе не учитывают доступный игроку ростер, вложения, скорость, световые конусы, врагов и конкретный режим.

## Источники, которые не подтверждают команду сами по себе

- [HSR-Build](https://www.hsr-build.com/about) полезен для справочных данных, которые он связывает с Project Yatta, но сам описывает подборки команд и тир-листы как редакционные. Этот источник не принимается в одиночку как доказательство лучшей/актуальной команды.
- [StarRailBuilds — MoC архив](https://www.starrailbuilds.com/endgame/memory-of-chaos) показывает архивный набор 4.4.1 с данными от 20 августа 2026 года. Не использовать его как актуальное подтверждение для 4.7, пока не появится свежий срез.
- [StarGuide](https://starguide.gg/best-teams) ранжирует составы по своей модели/оценкам синергии. Это можно открыть как гипотезу для проверки, но не принимать как статистику реальных прохождений.
- Реддит, Discord-сообщения, комментарии и ролики без проверяемого автора, версии и конкретной метки «гайд/билд» не являются подтверждением сами по себе. Они могут помочь найти первоисточник.

## Правило для будущих изменений в проекте

1. Сначала определить режим и задачу команды: MoC, PF, AS, Anomaly Arbitration или конкретная механика/ивент.
2. Приоритет для статистики — свежая выборка прохождений с открытой методологией; для рекомендаций — только автор с подтверждённым HSR Creator статусом и пост с явной меткой «гайд/билд» и версией. Механику отдельно сверить с данными игры.
3. Если 4.7-данных ещё нет, оставить это явно указанным. Не подставлять 4.6.x-команду под видом актуальной и не заполнять пробел предположением нейросети.
4. Записывать доказательство рядом с командой: URL, дата проверки, версия, режим, точный состав, E-порог/световые конусы, метрика и краткая причина выбора.
5. Классы `verified-statistics`, `verified-guide` и `official-creator-guide` в коде не должны назначаться автоматически по домену или словам «guide/build» в заголовке. Класс назначается только после проверки конкретной страницы и условий.
6. Пользовательское подтверждение состава хранить отдельно от сетевого подтверждения. Пользовательская команда может быть правильным предпочтительным вариантом для его аккаунта, но не должна выдаваться за статистически доказанный топ.

При добавлении новых команд сначала искать точный состав в актуальном источнике. Если данных нет, показывать этот пробел явно; нельзя собирать четвёрку из отдельных синергий или общих ролей. Пользовательски подтверждённый состав хранить отдельно от статистического.
